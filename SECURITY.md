# Security Policy

## Supported scope

Security reports are welcome for the public companion code and repository automation in `sanskarIN/sql-master`.

## Reporting a vulnerability

For a potentially sensitive issue, do **not** publish secrets, credentials, private data, exploit tokens, or confidential documents in a public issue.

Contact:

- Support: **supportramsandesh@gmail.com**
- Business: **sanskarin@outlook.in**

Include the affected Part/path, environment, impact, minimal reproduction, and any safe evidence that helps confirm the issue.

## Security expectations

- No real credentials in source or examples.
- SQL values should be parameterized at application boundaries.
- Multi-tenant examples must preserve tenant identity in key and authorization paths.
- Runtime roles should follow least privilege.
- Paid/private manuscript artifacts must not be committed to the public repository.
- Dependency or CI changes should minimize token permissions and pin trusted actions to supported major versions or immutable revisions when appropriate.
